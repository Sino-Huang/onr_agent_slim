Using the ONR Operator Console

The Operator Console is a full-screen terminal UI that launches one mission at a time, shows what the agents are doing while it runs, and lets you cancel it cleanly. This guide covers a full session, from opening the console to recovering a run after a crash. Every screen image below is a real console render frame, committed under docs/design/operator-console/frames/.

1. What the console is

There are two programs. You only interact with the first one:

Operator Console (this TUI)

A Rust terminal app. You use it to pick a stack, type a Mission Intent, watch progress and cancel. It never starts simulators or agents itself.

Runtime Host

A local Python service (default http://127.0.0.1:8787). It starts and stops each run's Environment Stack, owns all run state and writes evidence under var/runtime-host/runs/<mission_run_id>/.

The launcher script starts a Host for you if none is running. Because the Host owns the run, closing or crashing the console does not stop the mission. See Recovery.

2. Before you start

  • Environment: the onr conda environment (the launcher activates it).
  • Model server: vLLM must be serving the configured model at http://127.0.0.1:11411/v1/models.
  • Sibling checkouts: onr_physical_runtime, the scenario inputs and the planner executables are needed even for simulated missions.
  • AirSim runs only: the Harbor engine and its settings, plus the sibling onr_solution producer. YOLO perception also needs yolo_weight/best.pt and ultralytics.
  • Terminal size: at least 100×30. Use 140×40 or larger to see the overview image and side panels; 160×45 works well for demos.
# one-time per shell
cd /data/ccu/sukaih/ONR/onr_agent_slim
source /home/sukaih/miniconda3/etc/profile.d/conda.sh
conda activate onr
curl --fail http://127.0.0.1:11411/v1/models   # is vLLM up?
bash scripts/vllm/start_vllm.sh                 # only if it is not

You don't have to check every prerequisite by hand. The console runs a preflight check and names exactly what is missing.

3. Start the console

./scripts/tui/start_operator_console.sh
# Inside tmux or herdr, use portable half-block graphics:
./scripts/tui/start_operator_console.sh --image-protocol halfblocks
# Give a slow, cold Host start more time (default 60 s):
./scripts/tui/start_operator_console.sh --host-ready-timeout 120
OptionMeaning
--image-protocol auto|kitty|sixel|iterm2|halfblocks|off How world and camera images are drawn. auto queries the terminal. halfblocks is the reliable choice inside multiplexers. off disables images. The ONR_CONSOLE_IMAGE_PROTOCOL environment variable sets the same option.
--host-ready-timeout SECSHow long to wait for a bootstrapped Host to become healthy.
http://127.0.0.1:PORTConnect to a Host on a non-default port.

The first run compiles the release build, which takes a while. Warm it up before a demo. While the Host boots you'll see a spinner. Host output goes to var/runtime-host/host.log, and if the Host fails to start, the console prints the last 20 lines of that log.

4. Choose a stack and a Mission Intent

The Launch screen has three areas. Stack (top left) selects what to run. Preflight (top right) shows whether it can run. Mission Intent (bottom) is the plain-language task for the agents.

  1. Pick a preset. Press Tab to reach the Preset field and ←/→ to change it. mission1-harbor is the simulated stack, which still uses the real world model, planners, belief service and vLLM agents. mission1-airsim uses the real Harbor engine. Other presets: mission2, mission3, mission4, joint, joint24, joint34.
  2. Set the toggles. AirSim, Perception (off/ideal/yolo), Updates and Sim limit. An option marked ✗ is unavailable for this preset, and the console explains why. For example, ideal/yolo perception needs AirSim, and only mission1-airsim plays the recorded engine scene they need.
  3. Pick an AirSim mode. With AirSim on, Harbor always starts. With perception off, the world model runs on simulated information and AirSim follows it for visualization. With ideal or yolo, the scene clock synchronizes the world model to AirSim and the perception module feeds it.
  4. Wait for preflight. ✔ pass, ▲ warning (launch allowed), ✖ failure (launch disabled). Press r to re-run it after fixing something.
  5. Write the intent. Type in the Mission Intent box. Enter inserts a newline here; it does not launch. Press F2 to insert a prepared prompt instead.
  6. Review. Press Alt+Enter (some terminals report Ctrl+Enter) to open the review screen.

5. Review and launch

Expect a long startup. The Host must bring the whole Environment Stack to readiness first. Simulated Mission 1 prepares surveillance planning views during startup, which can take noticeably longer than the physical runtime alone. Real missions run actual model inference and can take tens of minutes.

Progress: what happened, at three levels

Run Narrative → Mission Log Summaries → raw records. Each summary covers an exact range of operational records. Records that no summary covers yet appear under Live — not yet summarized. When the next summary arrives, they move under it without duplication.

  • ↑/↓ select; ←/→ or Enter fold/unfold

  • / search, Enter accept, n/N next/previous match
  • PgUp/PgDn scroll the selected-evidence detail

While the search box is open, typing is captured, so q, c and Tab are entered as text. Ctrl+C still exits.

8. When a mission is rejected

If the intent is not an operational objective the vehicles can carry out (try "buy me a coffee" from F2), the Hyper Agent rejects it. A prominent card shows the actual reason, the intent, the stage and how much work was done.

  • Enter shows run details. In 3 Agents you can see the recorded reject_mission_intent tool call.
  • e returns to Launch with the same preset and toggles so you can write a new intent. It becomes available only after cleanup (summary flush and stack teardown) has finished.
  • e works the same way after any finished run, not only rejections.

9. Cancel, exit or detach

c then Enter: cancel the run

Stops this run's worker and its Environment Stack. The console stays open. Teardown can take up to about 9 s. The Harbor configuration is restored even after a forced teardown.

q or Ctrl+C: managed exit

Quits the console. If you own an active run, the console asks you to confirm cancellation first. A second Ctrl+C does not silently abandon the run.

Ctrl+Q: detach

Quits without cancelling. The Host, the run and your owner session keep going, and relaunching the console reconnects you to the same run.

Don't kill the Host to end a demo. Use c or q. A killed Host cannot resume its run. See below.

10. Recovering after a crash

What happenedWhat survivesWhat to do
Console killed (even kill -9), terminal closed, or Ctrl+Q The Host and the run keep going. Your Console Session is saved at ~/.local/state/onr/operator-console/session.json. Run the launcher again. It reconnects to the same Host and recovers ownership of the run, including the ability to cancel it.
Your saved run is gone, or the Host is running a newer run Nothing to recover The console returns to Launch and does not take over someone else's run.
Host killed The run cannot resume Restart the Host, for example by running the launcher. It removes the leftover processes it can prove belong to that run and records the run as failed · host_interrupted.

A console that reconnected to an already-running Host never stops that Host when it exits. Only the console that bootstrapped the Host does.

13. Troubleshooting

SymptomLook here
Host never becomes healthyvar/runtime-host/host.log; try --host-ready-timeout 120 for a cold start.
Launch disabledThe ✖ line in Preflight names the cause. Fix it, then press r.
Stack stuck on ◐ starting6 Stack: select the service and read its log tail. Full logs: <run_root>/services/.
Run failed with a short reasonThe run card shows a sanitized reason and stage. The full traceback is in <run_root>/worker.log.
No camera source on AirSim<run_root>/world-frames/camera-capture.json: state (capturing, unavailable, stopped) and reason.
Images broken inside tmux/herdrRelaunch with --image-protocol halfblocks, or use off.
Is an AirSim + YOLO run actually correct?A green TUI is not the acceptance gate. Run python scripts/audit_live_demo.py --run-root var/runtime-host/runs/<id> --mission-mode mission1 --perception yolo and require a PASS in live-acceptance.json.

<run_root> is var/runtime-host/runs/<mission_run_id>/. Don't change global transport or storage paths to run a demo; the Host writes each run's configuration there.
